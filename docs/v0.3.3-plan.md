## 2. What needs modification

1. **Instance model.** Today an "instance" is just an installed (version, loader) pair. v0.3.3 needs per-instance
   name, icon, Java, RAM, game directory, loader version, launch arguments, last-played, clone and delete. This
   must be additive: a new `unlimited-instances.json` store keyed by the instance folder id, layered over the
   existing `unlimited-install-<mc>-<loader>.json` markers.
2. **Older Minecraft.** `supported_release` accepts only 1.20.5+ and `install` refuses anything that does not ask
   for Java 21. To offer 1.8/1.12/1.19 families this must become: releases 1.8+ installable, required Java read
   from the version JSON, `minecraftArguments` (pre-1.13) supported, native jars extracted for those versions.
3. **Java.** `runtime.rs` is written around Java 21 (`REQUIRED_MAJOR`, `temurin21-binaries`, `temurin-21`).
   It needs a `major` parameter (8 / 17 / 21) and per-version compatibility instead of one global rule.
4. **Crash recovery.** `crashlog.rs::diagnose` returns one sentence. v0.3.3 needs a structured diagnosis
   (cause, evidence, confidence, suggested fixes) and an Apply Fix command that backs up and changes one setting.
5. **Offline theme.** Too dark; needs a lighter, readable ink theme with a clear active state.
6. **Home / Versions / Library.** Home shows `1.21.11 Fabric` as its headline and only installed cards; Versions
   and Library are one page. These are frontend rewrites on top of the existing data.
7. **Version metadata.** `0.3.1` in `package.json`, `tauri.conf.json`, `Cargo.toml`; About/CHANGELOG.

## 3. What is missing entirely

- Recently Played (only a single `cirrus.lastPlayed` key exists in localStorage).
- Version families with artwork, and Versions/Library separation.
- Vanilla/Fabric install-type picker with a loader version choice; OptiFine.
- Instance clone / delete / repair / per-instance settings.
- Java page, per-instance Java, installing a Java other than 21.
- Crash diagnosis UI and safe fixes.
- Automatic launcher updates.
- First-run setup.

`Button`, `Card`, `Badge`, `Banner`, `Skeleton`, `Spinner`, `Toasts`, `notify`, `InstallProgress`, `ModUpload`,

## 5. Technical limitations and blockers

- **OptiFine.** There is no official, machine-readable release API and the official installer is a GUI application;
  running or patching it silently would break the "verify before claiming compatibility" rule. v0.3.3 ships the
  OptiFine card as *unavailable* with an explanation unless a verified installer path is provided. This is flagged
  as a genuine blocker, not mocked.
- **Updater signing.** Tauri 2's updater verifies a minisign signature with a public key compiled into the app. The
  public key, the private key in CI and a hosted `latest.json` must come from the project owner (see §8).
- **No Rust toolchain in this environment.** The backend is written carefully and verified by the Windows CI
  workflow (`cargo test --lib`, `tauri build`), not locally.
- **No network to Mojang/Fabric/Adoptium in this sandbox**, so downloads cannot be exercised end-to-end here. Tests
  cover pure logic (path building, legacy argument resolution, diagnosis, config store) instead.
- The app is Windows-only today (`keyring` Windows backend, `creation_flags`); Linux/macOS are out of scope.

## 6. Phased plan (stages, each with its own commit)

- **B — Shell and pages.** Versions (families, artwork, search/filter/sort) and Library split; Home hero +
  Recently Played + news + shortcuts; Offline theme; Discord hover; navigation entries.
- **C — Install and instances.** Install dialog (Vanilla/Fabric, loader version, progress), instance profile
  editor, clone, delete confirmation, repair, per-instance game dir/memory/Java/args, Fabric loader change.
- **D — Java and mods.** Java page (detected runtimes, compatibility per version, install 8/17/21, manual path,
  per-instance selection), Mods upload already present, wired to the selected instance.
- **E — Crash recovery.** Structured diagnosis, evidence, safe fixes with backup and verification.
- **F — Updates.** Tauri 2 updater plugin wiring, update banner, manual check, signature/key injection from CI
  secrets, changelog from the release manifest.
- **G — Polish.** First-run setup card, empty states, version 0.3.3 metadata, tests, Windows build, screenshots.

## 7. Data model (new)

`unlimited-instances.json` next to the install markers:

```json
[{ "id": "fabric-loader-0.17.0-1.21.11", "minecraft": "1.21.11", "loader": "fabric",
   "loaderVersion": "0.17.0", "name": "Survival", "icon": 2, "javaPath": null,
   "memoryMb": null, "gameDir": null, "jvmArgs": "", "lastPlayed": 0, "clonedFrom": null }]
```

Existing markers stay the source of truth for "what is installed"; the store only adds per-instance preferences,
so an upgrade never loses an installation.

## 8. What the project owner must provide

1. **Updater:** `TAURI_SIGNING_PRIVATE_KEY` + password as GitHub Actions secrets, the matching public key in
   `tauri.conf.json`, and a release host serving `latest.json` + the signed `.exe`/`.nsis.zip` (GitHub Releases
   works). Also decide the release channel names (stable now, beta later).
2. **Discord invite URL**, if the current one should change.
3. **OptiFine:** an approved download/install path (official installer is GUI-only) if OptiFine support is required.
