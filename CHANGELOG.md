# Changelog

Every big change gets its own version number. Small fixes bump the last number (0.3.1), new features and redesigns bump the middle one (0.4.0).

## Unreleased (0.4.0) — Maple Client

- **The launcher is Maple Client.** The name, window title, installer metadata, About page, footer, boot screen, licence and every user-facing string now say Maple Client. The maple-leaf mark replaces the cloud, drawn as SVG so it stays sharp at every size, and `branding/make_maple_icons.py` rasterises the same outline into `public/brand/*`, `public/favicon.png` and every `src-tauri/icons/*` file including the multi-size `.ico`.
- **One brand colour, `#E25303`.** Maple orange is the accent for the selected navigation section, primary actions, progress, focus rings and active controls; surfaces stay neutral. No component is orange "because brand": the classic white-accent look was replaced only where the accent already meant something.
- **Navigation without icon tiles.** Sidebar icons and labels sit directly on the rail - no boxes, borders or per-item fills. The selected section is marked with a thin orange bar and an orange icon; every other icon stays still. The notification bell is the only animated icon, and only while something is unread.
- **Instances are bigger and clearer.** The card grid uses full-bleed family artwork at a comfortable size, a larger version title, the loader and mod count, and a full-size Launch button next to Mods. A picture chosen for an instance replaces the family art, and Launch on an undownloaded instance goes to the real set-up flow instead of failing silently.
- **Add version and Create instance are separate actions.** The Instances header has *Add version* (the Versions catalogue) and *Create instance* (a new two-step dialog). Step one mirrors the reference: search, Custom setup, Start from a mod or modpack, Upload a modpack, Import instance. Step two configures a picture (upload, randomize or one of the eight icons), name, loader and game version from Mojang's catalogue, then writes a real instance through the backend. Only Vanilla and Fabric are offered because those are the loaders this build can install; the modpack, upload and import entries are shown as unavailable with the reason, not as dead buttons pretending to work.
- **Instances created in the launcher appear immediately.** The backend lists instances that have a saved record but no downloaded game files yet, so a newly created instance is visible before its first launch.
- **Classic and Colorful both use maple orange.** Classic is the neutral identity with restrained orange accents. Colorful fills the window with the owner-supplied Minecraft background (`src/assets/backgrounds/colorful.jpg`) on every page, behind warm translucent panels and the same orange; the launcher itself ships no Minecraft artwork. The first-launch chooser, persistence and the Settings switch are unchanged, and switching still touches no account, instance or setting.
- **Settings is one organised widget.** The categories are General, Minecraft (versions, folder, launch, Java, memory), Appearance, Downloads and updates, Account and Discord. Rich Presence moved into its own Discord tab with a real connection status from the backend, and the same Discord button treatment is used in Settings, About and the footer.
- **Delete is unmistakably destructive.** Danger buttons are red in every theme with a white trash glyph, and the existing confirmation still lists what the folder holds and keeps it unless the person opts in.
- **Character is now Skins, with capes.** The section and page are called Skins everywhere, and a dedicated Cape panel shows the cape the signed-in account actually owns, next to the figure. Minecraft has no public cape-changing API, so Maple shows and never fakes one; Maple cosmetics are listed only when a platform confirms ownership.
- **Servers lists real partners with live status.** Vanguards is configured from its Modrinth listing (`vanguards.ggwp.cc`, Paper, 1.21.11) with its official icon, and every live field — online state, player count, version, MOTD, latency, icon — comes from the game's own Server List Ping run in Rust (`server_status`), cached for 45 seconds. Vanguards publishes its real port only in a `_minecraft._tcp` SRV record (`aurora.dathost.net:17515`), so the check follows that record the way the game does, over DNS-over-HTTPS, instead of reporting a healthy shared-host server as offline. A check that fails says *Status unavailable*, an unanswered server says *Offline*, and neither invents a player count. Join starts the selected instance through the real launch flow and passes `--quickPlayMultiplayer`, which needs 1.20 or newer; older versions are told so instead of being launched into the title screen.
- **Updates stay inside the launcher.** Settings no longer sends anyone to GitHub. The private distribution model, the missing signed feed and the key/signing requirements are written down in `docs/launcher-updates.md`; nothing insecure was enabled to make it look finished.
- Version metadata is 0.4.0 in `package.json`, `src-tauri/tauri.conf.json` and `src-tauri/Cargo.toml`. The Tauri identifier stays `com.limitedfps.app` on purpose so existing settings, instances and accounts keep their folder.

## 0.3.3 — Classic layout, a theme choice, and real update controls
- **The vertical sidebar is back.** Play, Instances, Versions, Mods, Modpacks, Servers, Character, News and Settings each get an icon and a label in a left rail; Settings sits at the bottom. The top bar keeps only the play mode, notifications, the account and the window buttons. Pages that were not implemented (Chat, Media) are not invented.
- **Home is a classic launcher again.** The branded hero runs across the top with the version line and the one **Play** button in the middle of the screen; **Recently played** follows as image cards, and **Quick join** and **News** sit below. The layout collapses to one column on narrower windows.
- **Image version cards.** Instances are full-bleed Minecraft artwork with the instance name, `1.21.11 Fabric`, `LOADER 0.17.2 · 6 MODS`, the last-played line, a Selected badge, and Launch plus Mods (Fabric) actions. Cards use the same `btn` styles as the rest of the launcher; nothing was re-skinned. Library uses them too, and their settings and folder buttons still work per instance.
- **Classic and Colorful themes.** The first launch asks which look to use with two preview panels; the choice is stored and never asked again. Settings → Appearance switches immediately between Classic, Colorful and Light, and changing it touches no account, instance or setting. Both themes share one component tree; Classic keeps the monochrome chrome, Colorful restores the bright cube key art with the old blue Play button over neutral (not blue-washed) panels.
- **One button system.** Every action is the same inline-flex control with a visible surface, so icons and labels share one vertical centre and buttons such as *Install performance pack* are no longer invisible over artwork. Hover changes colour only, the press moves one pixel, and disabled buttons stay legible.
- **Version artwork follows the version.** Cards now use the key art of their Minecraft family (1.21, 1.20, 1.19, …) instead of a random crop, so two instances of different versions never look the same.
- **Mods land in the instance's own folder.** Installing, listing, switching or removing a mod resolves the selected instance's real game directory (including a custom folder or a cloned instance) instead of assuming the default profile folder, so a downloaded mod appears in the game that will load it.
- **Update checking is configurable.** Settings → Updates has an on/off switch for the start-up check (on by default) while manual checks keep working. Installation remains disabled until signed releases are configured; the exact requirements are in `docs/launcher-updates.md`.

## 0.3.3 — Library and Versions split apart, Java 8/17/21, crash diagnosis, update checks
- **Home is a launcher again.** A branded hero ("Sky is the limit.") replaces the version string as the headline, with the selected instance underneath, launcher shortcuts, a **Recently played** list (newest first, selection, one-click play, honest empty state) and project news. The version and loader are secondary information.
- **Versions and Library are separate pages.** Versions lists what can still be installed, grouped into families (1.21, 1.20, 1.19, 1.18, 1.17, 1.16, 1.12, 1.8 and older) each with its own artwork, an expandable release list, search, an installed filter and newest/oldest ordering. Library lists only installed instances, with per-instance settings, folder, play and duplicate/repair/delete. A version becomes an instance only after its installation succeeds.
- **Installing is a real choice.** A dialog offers Vanilla (grass block) and Fabric (official mark) with a Fabric Loader selector defaulting to the recommended stable build; OptiFine is explained instead of being offered, because no verified non-interactive installer exists. Progress uses real download counts, can be cancelled, and a failed or interrupted download changes nothing.
- **Java 8, 17 and 21.** Detection lists every runtime with its path and whether it fits the selected Minecraft version, Java 8/17/21 can be installed into the launcher's own folder (Temurin, checksum-verified), and an instance can pin its own Java while the launcher keeps its automatic choice. Older releases (1.8+) launch through the legacy argument format and native extraction.
- **Crashes are explained.** The crash screen names the likely cause with a confidence level, quotes the lines it is based on behind a disclosure, and offers safe fixes (memory, repair, loader, mods, Java). Applying a fix asks first, keeps a settings backup, changes only that instance, and says what happened. Unknown crashes are labelled as unknown, with the raw report one click away.
- **Instances are independent.** Name, icon, memory, Java, folder, JVM arguments and Fabric Loader can differ per instance; cloning copies worlds/mods/settings into the copy's own folder; repair re-checks Minecraft's files without touching worlds, mods or screenshots; deletion asks first, defaults to keeping the folder, and lists what the folder holds.
- **Offline mode is lighter.** Graphite surfaces, readable type and a lighter picture veil replace the near-black sheet, with a calm cross-fade; offline names stay clearly marked as unverified.
- **Discord button** uses the white mark and turns Discord brand blue on hover, with a short transition; Rich Presence is untouched.
- **Launcher update checks.** Cirrus asks the official GitHub releases API (HTTPS, host allowlist, strict newer-than comparison), shows current → latest with notes in a dismissible notice and in Settings. Automatic installation stays off in this build because it needs a signed release and the updater public key; the button opens the official release instead of pretending to install.
- Version metadata is 0.3.3 in `package.json`, `src-tauri/tauri.conf.json` and `src-tauri/Cargo.toml`.

## 0.6.0 — Library-first versions, a calmer launch panel, and an explicit play mode
- **Versions is a library.** Installed versions are cards inside the library, each showing the Minecraft version, the loader and its build, the installed mod count, and a Selected badge for the one that will run. The whole card selects that installation at once, and its Launch button starts the game with it; Mods jumps straight to that version's mods. A search box and an all/Fabric/Vanilla filter sit above the list.
- **Add Version** is a button above the version list. It opens the Mojang catalogue in its own window, with the release/snapshot switch, search and every installed/not-installed state, so versions that can be added are clearly separate from the ones already on the PC. Picking one applies it and Play downloads whatever is missing.
- **The Launch panel is one column of decisions:** the account and play mode first, then the selected version with its loader and install state (never a second version picker), then the one Play button. Memory, Java and the game folder moved into an expandable “Advanced launch options” section.
- **Online / Offline is a switch in the top bar.** Online uses the existing Microsoft sign-in; Offline takes an unverified name, says so plainly, and gives the window an ink-and-paper treatment: pure black ground, white hairlines, squared corners, no picture and no colour, in both appearances. Offline mode never shows the Microsoft profile as the player and offers no account skin or cape.
- **One click, one action.** A small single-flight gate now wraps starting the game, downloading game files, stopping it and opening a folder, so a rapid second click is dropped instead of reaching the desktop twice; the gate opens again as soon as the work finishes or fails.
- In-game Cirrus typography: the small UI face is slightly larger and mod descriptions use the body face, so names, categories and descriptions hold their hierarchy at every GUI scale.

## 0.5.0 — Your own mods, texture packs, and a real character viewer
- **Upload mods:** the Mod manager takes .jar files from your PC (the native file picker, several at once, or drag and drop). Each file is read before anything is written: the archive has to be a readable Fabric mod with a usable id, its `depends.minecraft` range has to include the profile's version, and its required mods are checked against what is installed. The list shows the mod's own name, version, id, size, icon and every warning or error; a file that fails is never installed. A mod that is already installed, or a file with the same name, is only replaced after an explicit tick, and the older copy is removed only once the new file is safely written.
- **Texture Packs** is a second tab of the same Browse page, with the same search line, site switch, sort and paging as mods. It browses Modrinth and CurseForge resource packs for the selected Minecraft version, filters by resolution (16x through 512x), and shows thumbnails, author, downloads, description and the site each pack comes from. Opening a pack gives a large preview gallery, its supported versions, resolution, file and source; Install downloads the published file, checks its checksum, confirms it really contains a `pack.mcmeta`, and puts it in that version's `resourcepacks` folder. A pack is never switched on automatically: Installed lists what is there, switches a pack on or off by editing Minecraft's own `options.txt`, and removes files without touching mods.
- **Character viewer:** the skin preview is now a proper model viewer. Both Classic and Slim bodies are built from the skin's own pixels in CSS 3D, with the jacket, sleeves, trousers and hat outer layers, the account cape, per-face lighting and a floor shadow. Controls are small icons: front, back, left and right views, auto-rotation, a camera reset, and zoom in/out (the mouse wheel works over the stage). Dragging turns the figure with momentum and arrow keys turn it too; auto-rotation is one GPU animation rather than a frame loop, and changing skins rebuilds only the figure.
- New browsing cache for pack searches and details (five minutes, small and bounded) so going back to a result costs no request, and network failures, empty results and a missing CurseForge key each get their own honest state.


## 0.4.0 — Interface refresh: monochrome shell, centred Home
- New palette, taken from the Cirrus mark: pure black and near-black surfaces, white for important text, icons, active states and highlights, and neutral grays for panels, cards, borders and secondary elements. No blue, cyan, purple or other hue anywhere; contrast, spacing and type carry the design. One set of tokens drives every page, in both appearances.
- The one filled control in the interface is the primary action, painted in the highlight colour with its type cut out of it (white on black in the dark appearance, black on white in the light one). Everything else is a flat gray surface with a hairline border, so the eye always knows where to start.
- Home's light behind the menu is now a soft shadow rather than a coloured glow, and the backdrop picture is held back toward monochrome so the mark and the white type stay the loudest things on screen.
- Home is a game menu again: the Cirrus mark and wordmark centred over the picture, the version about to run, one wide Play button with the only light in the interface, then the account line. Installed versions sit in a dock along the bottom.
- The menu fades up once when Home opens, a beat apart per element; nothing loops. Reduced-motion settings still switch all of it off.
- Top bar: the page icons sit directly on the strip, gray until their page is open, then white with a short underline. No pill, tile or plate behind them; the account is borderless until it is touched.
- Pages breathe: a card is a section marked by one hairline and space, not a near-black plate on the page. Browsers and the settings rail are separated by a rule instead of a panel, and the empty states lost their dashed boxes.
- Selection is a line: segmented controls, the settings list, the mod categories and pagination use white text with a short underline or rule for the active choice. No filled black selection blocks.
- Icons are free of containers: card, navigation, empty-state, version-picker and mod icons sit straight on the surface in white or gray, with artwork keeping its own proportions.
- Browse and installed mods read as editorial lists: icon, name, author and description on one line, actions at the end, separated by hairlines. The grid/list switch changes the flow without adding boxes.
- Buttons, fields and the account drawer keep the same flat skins, hover colours and one-pixel press; only overlays (menus, dialogs, the drawer) keep a solid fill.
- The Home backdrop's dark layer is now strongest behind the menu, so the picture stays visible at the top and the text stays readable.
- The in-game Cirrus screens (Fabric) keep the same palette and now share the launcher's open layout: one flat page, a single hairline between the rail and the content, sections marked by a top rule, free-standing icons, and category or page selection as a short white rail instead of a filled plate. The dashboard and appearance screen use the same rules; the HUD editor keeps its own layout and its feature code is untouched.
- The in-game mod library is one open page: a header with the brand, page name, filter count and theme, a quiet category rail with a hairline divider, a search line with a favourites filter, and a single column of mod rows. Rows (drawing and clicking) share one geometry record, so a click always lands on the row it hits; names and descriptions are shortened with an ellipsis, and ON/OFF is quiet text rather than a badge.
- Small windows keep the in-game layout honest: the mod library and dashboard rails are measured from the bottom up, so Done/Close and the page links hold their spacing while the category links take only the band above the HUD Editor (a short screen shows fewer of them instead of stacking onto it), and the appearance screen's preview pair gets shallower so its buttons stay on the page.

## 0.3.2 — Character Studio, icon navigation and a real version picker
- Home opens on the new forest-lantern artwork (`src/assets/backgrounds/home.jpg`) with a lighter dark layer over it, so the picture shows behind the title and Play button.
- The account chip opens a panel on the side of the window instead of a menu in the middle. It offers both ways to play in one place: an offline ("cracked") username with validation and a "Use this name" step, and the Microsoft account.
- Cracked play now works from the account panel: the name is stored, the header and Home show that player (with an "Offline" tag and no borrowed skin), and Play launches Minecraft in offline mode with it. Signing in with Microsoft switches play back to the real account.
- Removed the "Manage account" button from the middle of the Home identity row; managing accounts lives in the side panel.
- New startup screen: the Cirrus cloud mark on black with a small loading circle, shown while settings load and fading away when the window is ready.
- Character Studio replaces the old skin page: the account's real Minecraft character fills the large central stage, with its own skin, arm model and equipped cape read from the Minecraft profile, a live sync indicator, and an honest error state when the profile cannot be read.
- Skin changes go through the account: choose a 64 × 64 PNG (or drop it on the stage), copy a skin from a username or texture link, then apply it to the Minecraft account. Applying or refreshing updates every head, the dashboard and the figure through the shared appearance cache, and switching accounts swaps the whole character.
- Better 3D figure: bigger stage, smooth drag-to-turn with inertia, arrow-key turning, zoom slider with ± buttons, directional lighting on every side of every body part, a floor shadow, Classic and Slim bodies, legacy 64 × 32 skins and the account cape with its own shading.

- New Play button: solid accent surface, one-pixel press, colour-only hover, explicit launching state with a spinner, and a flat disabled state when the game cannot start.
- New version picker instead of a plain dropdown: a trigger card showing the chosen version, loader and install status, plus a panel with installed-on-this-PC shortcuts, search, All/Releases/Snapshots filters, per-version install labels and the Java check. The panel flips above the trigger and stays inside the window.
- Discord keeps its official mark with a quiet blurple colour change and no glow, lighting or movement.

## 0.3.1 — Minecraft identity, real player preview, no developer settings
- Microsoft sign-in opens in a dedicated sign-in window by default; the device code stays as a fallback.
- Account menu and Accounts page show the real Minecraft player head, player name, formatted UUID, skin model, equipped cape and Minecraft ownership. Account switching and removal stay in the same place.
- Several Microsoft accounts can be saved and switched without signing in again; each token lives in its own Credential Manager entry.
- Official Microsoft and Minecraft brand marks on the sign-in button and account card.
- Character: the real character is the default preview (own skin, Classic/Slim model, own cape), with drag-to-turn, zoom, a cape chooser, four original Cirrus skin presets, PNG upload and a one-click restore of the previous skin. The Cirrus cape is clearly labelled as a local preview.
- Header uses the transparent Cirrus cloud mark instead of a black tile.
- Removed Developer options and the Azure Application (client) ID from every user-facing screen. The app ID is built into the build, still overridable with `LIMITEDFPS_MS_CLIENT_ID`.
- Fixed real skin and cape loading: Mojang still returns `http://textures.minecraft.net` texture addresses, which the downloader previously rejected as insecure. They are now validated and upgraded to HTTPS, so real heads, skins and equipped capes appear instead of the labelled fallback.
- One shared appearance cache keeps every head, the dashboard and the 3D character in sync; Refresh and account switching update all of them, and 64 × 32 skins use the correct legacy body layout.
- Appearance lookups are cached in the backend for five minutes, so the account menu and Skins page do not re-download the same skin.
- New shared control layer for every button, icon button, segmented control and navigation tab: solid surfaces, a one-pixel press, a 120 ms release, fixed heights, and explicit loading, disabled and keyboard-focus states. No cursor light, sheen, glow or hover lift.
- Download panel now shows the real stage, percentage, average speed, time left and elapsed time from the bytes the backend reports, with a safe cancel and clear success and failure states.
- Mojang's whole version list is grouped into releases and snapshots and can now be searched and filtered by type. Snapshots and releases this build cannot install are marked as such instead of looking installable, the selected version shows whether it is installed, and the Java major from Mojang's manifest is compared with the Java Cirrus found.
- Settings are grouped into Game, Performance, Appearance, Account and More, with a new Account section, Minecraft window size and extra JVM options.
- The character preview stands still, turns only when dragged, can be refreshed when a skin changes, and falls back to a clearly labelled default look instead of a blank square.
- Accounts page gains the full 3D character, an active-account marker, add-account and a two-step remove confirmation.
- Toast notifications for sign-in, expired logins, downloads, launches and missing Java, matching the notification bell.
- Home shows who is signed in, the account's ownership and skin model, the install state and the last played version.
- A failed game download can be retried without leaving the panel.
